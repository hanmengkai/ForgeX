# ForgeX 2.0 全量测试修复验收

日期：2026-10-12。分支：`2.0`，修复基线：`2b071c2`。验证环境：本机 macOS 27.0.1、Node.js 24.21.0，业务测试与浏览器均使用隔离预约样板。

## 修复结果

原 8 项失败全部修复：

| 原问题                  | 修复                                                                              |
| ----------------------- | --------------------------------------------------------------------------------- |
| Runner 日志 6 项失败    | 补充 macOS 系统进程启动身份查询，使单实例锁、恢复及签名证据日志正常工作           |
| 扩展管理员示例 1 项失败 | 提供 POSIX 绝对路径示例，按本机平台验证；保留 Windows 示例和严格的本机路径校验    |
| 深色主题契约 1 项失败   | 检查现有验收标题、结果和 `.button.primary` 的颜色及对比度，移除对已删除类名的依赖 |

直接运行普通 `npm test` 还复现了 45 项失败；原来需要外部设置短 `TMPDIR` 才会收敛到上述 8 项。本轮将 macOS 测试临时目录设置为系统规范化短路径，保证严格路径测试使用有效输入。生产路径、符号链接、文件权限、凭据和工作树边界检查没有放宽。

设备 Worker 自身也改用 macOS 短 Socket 目录，并在显式设置长私有临时目录的情况下实际验证互斥与释放，不只依赖测试环境设置。浏览器原先的桌面首屏高度为 132.09375px，超过原 132px 上限；收紧标题下方间距 1px 后通过，保留原字号、容器留白和高度断言。

macOS 的进程标识组合启动会话 UUID 与 UTC 秒级启动时间；通过固定绝对路径调用系统工具，参数只包含经过校验的 PID，不执行业务 Shell。只有内核 `ESRCH` 确认 PID 不存在；工具错误、权限不足和异常结果均保守返回未知。启动身份发生变化时可以回收旧锁，身份未知时原锁持有者保持不变。同秒 PID 复用无法区分时保守阻塞，不宣称旧进程已经退出。已验证真实子进程启动和退出、并发争锁、PID 启动身份变化及未知身份拒绝抢占。

实现参考 [Apple 的 ps 源码](https://github.com/apple-oss-distributions/adv_cmds/blob/main/ps/print.c)和 [XNU 启动会话标识](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/kern/kern_sysctl.c)。主题测试按 [W3C 的文字对比度说明](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)检查相关文字达到 4.5:1；此结果只涵盖被检查的组件，不代表整站无障碍认证。
