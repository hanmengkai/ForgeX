# 2.0 交付界面改版验收

日期：2026-10-12。分支：`2.0`。验证环境：macOS、Node.js 24、Chromium、本机隔离样板。

## 页面变化

- 交付列表支持名称和目标搜索，以及待我处理、进行中、阻塞、已关闭筛选；新建表单按需展开。
- 详情用需求、设计、开发、测试、发布、验收六段表示流程。独立设计审核、恢复审批和恢复执行均保留真实阶段提示。
- 当前材料、全部成果、审批与记录、关联 Bug 分开阅读。需求和设计以版本 1 的结构化阅读模型呈现，并展示前版正文的实际增删；旧服务未返回结构化文档时仍可读取原文本。
- 桌面审批区位于详情右侧，窄屏优先显示当前状态与审批；通过、异议、驳回有不同视觉层级。提交确认绑定需求、岗位和记录版本，取消不写入；内容改变时清空旧意见并要求重新核对。
- 首页直接读取 `/api/v2/lifecycle` 的实际待办、阻塞和近期交付，不再将旧版需求统计当作完整交付数据，也不把读取成功等同于平台健康。
- 主导航统一为工作台、交付需求、我的审批。旧需求工具和工具操作确认保留在“其他工具”；对应旧版 API 和功能仍保留。
- 执行器页读取版本 1 的执行器视图，展示连接、能力、当前任务、心跳和登录核对。心跳超过 45 秒显示离线；无登录证据不计入可接任务；等待完成回执确认时不显示空闲可接任务。

新增接口：`POST /api/v2/executor/heartbeat` 和 `GET /api/v2/workers`。执行器只能通过自己的连接身份上报；纯需求方账号不能读取团队内部执行器。控制面保存显示名、状态、能力和执行器公钥的不可逆身份指纹，不读取或接收 Codex 登录文件。

当前用户 Codex 登录核对使用本机已验证的 `0.162.0-alpha.17.2` CLI 固定命令。现场返回 `logged_in`；其他版本或不能确定的错误返回“尚未核对”。登录状态核对不发起模型任务，也不输出原始登录信息。

## 验收结果

| 验证                    | 结果                         |
| ----------------------- | ---------------------------- |
| `npm test`              | 770 通过、0 失败、9 条件跳过 |
| `npm run typecheck`     | 通过                         |
| `npm run test:coverage` | 通过，原阈值未改变           |
| `npm run build:all`     | 通过                         |
| `npm run test:e2e`      | 6 项通过                     |

覆盖率：语句 81.40%、分支 72.01%、函数 83.67%、行 82.61%。条件跳过仍为 5 个真实 PostgreSQL、3 个 Windows 专用和 1 个显式实时模型场景。

浏览器验收由六个不同样板账号实际执行产品审核、需求确认、独立设计审核、代码审核、测试报告审核、测试环境验收、三方发布批准、三方线上验收与关闭后 Bug 提交。样板执行真实 Git、自测、业务 HTTP 测试和隔离部署，Agent 响应采用明确的固定样板。本轮没有新增实时模型任务，没有连接真实生产。

另验证首页待办能打开对应设计审核、六段流程、审批取消及 Escape 关闭、四个执行器状态、390px 窄屏无横向溢出、浅深主题，以及旧需求工具、长详情弹窗、登录与会话恢复。截图经实际查看，调整了深色状态文字的对比度。
