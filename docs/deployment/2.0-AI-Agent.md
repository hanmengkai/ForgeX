# 2.0 真实 AI 隔离样板接入

## 使用方式

在当前 macOS 用户下执行，不创建新系统用户。使用已登录的本机 Codex CLI；账号信息、登录缓存、模型配置均留在客户设备，控制面不接收凭据。本轮已核对的新版 CLI 为 `0.162.0-alpha.17.2`；不自动接受未经权限验证的新版本。旧隔离启动器继续使用原 `0.147.0` 协议，不伪造不同系统身份的证明。

```bash
codex login status
npm run p0:ai:sample
```

实时验收命令使用真实模型，并以六个不同测试角色提交审批。验收过程覆盖独立设计审核的驳回与重设计、代码与测试审核、隔离测试部署、三方放行与验收、关闭、关联 Bug 修复和隔离恢复。结果保存在 `.forgex-local/p0-ai/<时间>/`，包括 AI 原始结构化方案、会话标识、审批与任务证据、业务制品和生成代码。它们不含模型凭据；该目录被 Git 忽略。结束后关闭环境进程并清理临时工作树。

正常控制台入口现在采用真实 AI：

```bash
npm run p0:console
```

另一终端运行：

```bash
npm run preview --workspace @forgex/web-console -- --host 127.0.0.1
```

访问 `http://127.0.0.1:4173/delivery`，使用原六种样板角色账号，密码均为 `P0-Sample-2026!`。需求、设计、开发和独立测试计划采用独立真实 Codex 会话；HTTP 测试和运维动作由可信执行器实际执行。各人工关卡需对应角色操作，模型无法自动代替人批准。`p0:ai:console` 是同一真实入口的直接命令。

`npm run p0:sample` 保留无需模型调用的固定样板回归，`npm run p0:fixture:console` 用于离线固定模板演示。它们不作为真实模型验收证据。

## 当前用户的登录与网络

运行器优先找到 PATH 中经过核对的新版本机 CLI，避免 npm 加入 `node_modules/.bin` 后误用旧版 CLI。未指定 `FORGEX_CODEX_MODEL` 时，只读取当前用户配置的模型名称，不继承其他工具、插件、MCP 或权限配置。可用该环境变量明确指定模型；不会自动换成别的模型来掩盖失败。

使用原 `CODEX_HOME`（默认 `~/.codex`）及当前系统用户身份；不复制登录文件到控制面，也不重写用户 `config.toml`。CLI 自动管理本地缓存，符合 [OpenAI Docs 的登录缓存说明](https://learn.chatgpt.com/docs/auth)。

显式代理环境变量会保留；没有代理环境变量时，读取当前 macOS 系统代理并转换为子进程 HTTP/HTTPS 代理，回环请求排除代理。CLI 日志及 SQLite 状态放在任务临时目录。环境不会继承控制面令牌、`OPENAI_API_KEY` 或 `CODEX_API_KEY`。认证不可用、结构化结果无效或模型调用失败时任务失败，不能用固定模板替代。

## 受控边界

本轮的当前用户模式仅支持 macOS；属于受控工具和进程权限模式，不能声称独立系统用户隔离。每个任务在单独 Git 工作树内执行。需求、设计及独立测试计划阶段发现代码变更即拒绝；开发只允许修改 `appointment.js`，提交由可信设备生成。

CLI 不加载用户配置和命令规则，关闭 Shell、浏览器、额外 MCP、插件等特性。只启用 ForgeX 的工作树 MCP；原生补丁和命令工具通过固定、已核对的 PreToolUse 守卫拒绝。守卫仅作用于本次调用，命令固定输出拒绝 JSON，不包含模型输入；调用前拒绝混入用户目录下额外的 `hooks.json`。因为此守卫由宿主事先核对，使用 CLI 的一次性 Hook 信任参数；不修改用户信任配置。[OpenAI Docs 的 Hook 执行与拦截说明](https://learn.chatgpt.com/docs/hooks)描述了这些接口及其限制。

系统沙箱另行禁止 CLI 在工作树与任务临时目录外写入，只有 CLI 必需的本地登录缓存、临时工具目录和安装标识例外。Hooks 是补充守卫，不作为完整系统隔离保证。原生补丁工具虽然仍在模型目录中，执行前会被拒绝；不能只依据 `shell_tool=false` 推断文件操作已封闭。

AI 编写的是预约业务函数，固定运行时负责 HTTP、页面、存储、健康检查和环境控制。制品包含协议版本、业务源码及运行时摘要；部署核对同一 Git 提交、制品和运行时。业务代码同时受 VM 超时、禁止动态代码生成、Node 文件与子进程权限、macOS 文件及出站网络沙箱约束。VM 本身不被当作安全边界。

独立测试 Agent 只生成验收条件与探针映射，不生成通过回执。固定可信探针实际执行创建、输入边界、幂等冲突、查询、容量和修复确认说明。若需求扩展出样板协议范围，任务阻塞，不能宣称全面覆盖。所有部署只监听 `127.0.0.1`；“生产”阶段指隔离发布环境。

此入口使用内存控制面及临时样板数据，供真实 AI 闭环验收。组织身份、真实业务仓库、长期任务恢复、真实 CI/CD 和客户环境仍需按 [P0 接入契约](2.0-P0.md)另行装配与验收。

本轮实际调用与回归结果见 [真实 AI 验收记录](../verification/2.0-AI-Agent.md)。
