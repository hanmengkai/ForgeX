# 2.0 Node/TypeScript 项目测试交付

本轮将正式 PostgreSQL 控制面与版本化 Node 项目适配器接通，试点为团队任务管理服务。交付停在测试环境验收完成后的“等待发布审批”。按用户决定，不新增托管 CI 或定时自动化；以下命令均由操作者手动执行。

## 当前电脑直接复跑

```bash
npm run p0:node:db:start
npm run p0:node:verify -- --fixture
npm run p0:node:verify
npm run p0:node:db:stop
```

第一条使用本机已安装在 `.forgex-local/node-p0-tools/postgres/bin` 的 PostgreSQL 17.10，并将完整连接信息保存在私有 `connection.json`，不会输出凭据。已有状态保留。fixture 不调用模型；第三条复用当前 macOS 用户 Codex 登录，会消耗账户额度。首次结果有待澄清问题、编译失败或测试失败时保持真实阻塞，不能填入固定成功值。数据库停止后仍可使用第一条恢复原记录。

其他测试机需准备 PostgreSQL 17 的可执行目录，通过 `FORGEX_POSTGRES_BIN` 指定给数据库命令；或者显式提供本机隔离数据库 `FORGEX_TEST_DATABASE_URL`。验证命令拒绝远程主机及名称不以 `_test` 结尾的数据库。没有配置不会创建或连接真实生产资源。

## 正式控制面与迁移

新增 `0027_lifecycle_artifacts.sql`，按既有统一迁移器顺序执行，不修改已发布迁移。`createProductionControlPlane` 同时装配 `PostgresLifecycleRepository` 和 `PostgresLifecycleArtifactStore`。制品传输继续使用 `/api/v2` 与 envelope v1，最大 128 KiB；原始字节按租户、项目、仓库、摘要及提交保存，不与旧 Preview 制品混用。下载重算摘要；相同内容重传幂等，损坏或冲突失败。代码结果仅在制品已保存后接受。

数据库故障修复或回退前先停止相关 Worker，并保留制品与交付证据。应用回退不能自动撤销数据迁移；新表应保留，不直接删除历史制品。`0026` 带来的新账号角色兼容要求仍适用。

## Node 项目配置 v1

执行器私有配置仍为 v2，在 `sample`、`adapter`、`nodeProject` 中只选择一个。`nodeProject` 包含绝对私有 `root`、`entrypoint`、`sourceFiles`、`runtimePath/runtimeSha256` 和 `suitesPath/suitesSha256`。路径与摘要由管理员登记；业务契约和独立套件由管理员维护，不能由开发候选修改。

开发使用隔离 Git 工作树，可信宿主生成提交，读取该提交内登记的 TypeScript 源码，严格编译后生成内容协议 v2：入口、JavaScript 模块与受信运行时摘要。当前范围为不超过 100 个纯业务模块、64 KiB TypeScript 源码及 128 KiB 制品，只使用 ES2022 标准库，不加载外部 npm 包、候选 tsconfig 或 npm scripts。受信运行时管理 HTTP、持久化和编号，业务默认导出同步处理函数，协议见 [项目契约](../../examples/node-task-board/project-contract.md)。这不是任意 Node 应用的通用部署承诺。

需求和设计阶段保持工作树无修改；开发仅允许登记文件变更。独立测试计划 v2 为受信 `suiteKey` 与验收条件索引的映射，条件标题也必须与管理员登记目录对应。重复、遗漏、未知套件、覆盖绑定错误及套件摘要变化均拒绝。模型不能提交命令或通过结论。远程 `HttpLifecycleAdapter` 增加网关请求 v3 `{ schemaVersion: 3, job, recoverOnly: false, testPlan }`；原执行/恢复 v2 请求保持兼容。远端网关还需按 v3 实现并自行现场验收，本轮真实运行采用本地受控 Node 适配器。

开发、独立测试和测试部署使用三个独立进程、身份及私有目录，通过正式制品 API 传输。没有生产执行器；Node 项目适配器对生产阶段返回明确阻塞。

## 失败边界与恢复

- 模型仅使用有界工作树 MCP，无 Shell、浏览器、用户扩展或生产权限。登录保留在本地；本轮复用当前用户登录，不宣称独立操作系统账号隔离。
- 候选模块在 macOS 系统沙箱及 Node 权限中运行。运行环境不继承用户变量；禁止出站网络、子进程及工作树外凭据访问。VM 限制执行时间和动态代码，只是附加限制。管理员配置、Worker 宿主、编译器和独立套件属于受信边界，不覆盖本机恶意管理员的威胁。
- 上传确认丢失时，只补传已自测的同一制品，不能重新调用开发模型。测试部署确认丢失时重传原签名回执，不重复启动环境。
- 部署恢复必须核对任务、输入摘要、获批提交和制品、部署地址、进程启动身份及实际健康状态。记录无法证明已有副作用时保持阻塞。不能通过删除日志或默认健康成功恢复。
- 验收结束停止本次控制面、Worker、测试与容量补测进程，保留 PostgreSQL schema、审批及本地证据。私有目录包含配置和令牌，不整体提交或分享。

详细结果见 [本轮验收记录](../verification/2.0-node-project-staging.md)。
