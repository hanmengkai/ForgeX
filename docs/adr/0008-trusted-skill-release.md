# ADR-0008：Skill 以内容寻址包和独立评测发布

## 背景

Skill 会改变 Agent 阅读文件、写入工作区、访问网络和运行命令的方式。仅在目录里填写“可使用”或上传一个同名文件，无法证明 Worker 最终执行的是哪份内容，也无法安全回滚。压缩包还会引入路径穿越、重复文件和解压膨胀等额外攻击面。

## 决策

- Skill 包使用规范 UTF-8 JSON 编码：顶层 `instructions` 对应 `SKILL.md`，资源只能位于 `references/`、`scripts/` 或 `assets/` 下。资源路径按 `/` 分段校验，不接受 `.`、`..`、空段、尾点/空格或 Windows 保留设备名，并按大小写折叠后去重，避免不同 Worker 物化出不同文件。
- 包和解码后内容均限制为 20 MB；二进制资源必须使用规范 Base64。Control Plane 不解压 ZIP/TAR，也不信任客户端自报的大小和 SHA-256。
- 每个清单绑定租户、项目、Skill、语义版本、实际包字节 SHA-256、权限声明和所需能力。同一版本的清单与制品都不可覆盖。
- 独立评测器使用 Ed25519 对固定字段顺序的评测负载签名。签名同时绑定 Skill 版本、制品哈希、完整规范清单哈希、评测套件版本、场景结果和授权范围；因此权限或所需能力被改写后，历史评测不能继续用于激活。
- 新激活必须使用仍在有效期内、全部场景通过、无严重失败且达到当前版本固定发布门槛的评测。回滚不是绕过：旧版本也必须有可信评测。后续若引入租户可配置门槛，必须把策略版本一并写入激活记录，而不能用新配置破坏历史快照恢复。
- 只有平台管理员可以发布或切换 Skill。当前激活绑定保存在严格快照中，完整激活/回滚历史写入独立审计表。
- 评测密钥分为“可签发新评测”和“只核验历史评测”。所有副本必须保留历史公钥，否则重启后不能安全恢复已经激活的 Skill。
- Skill 包、注册表和审计使用共享 PostgreSQL 仓储；内存实现只用于测试和单机开发。

## 后果

- Worker 可以按清单取得确切包字节，并在后续沙箱执行层按权限物化，而不是通过可变路径读取任意文件。
- 制品可以先写入再原子更新注册表；发布失败留下的内容寻址孤儿不会变成可执行 Skill，可由后续维护任务回收。
- `recordEvaluation` 只属于受信任评测适配器，不直接作为浏览器会话接口暴露；接入 API 时必须先验证评测器身份和租户范围。
- 当前单元测试验证运行时契约和 SQL 编排；真实 PostgreSQL 的约束、双连接并发和迁移执行仍属于最终集成验收。
