# ADR-0009：MCP 服务器先可信注册，再受控调用

## 背景

MCP 服务器可以读取项目、修改代码、访问外部系统或触发真实业务动作。仅在扩展目录中人工填写“可使用”无法证明设备实际连接的是哪台服务器，也无法证明工具名称、输入结构和风险等级没有漂移。把 URL、命令行或 Token 放进控制面，又会扩大凭据泄露范围。

## 决策

- MCP 清单按租户、项目、服务器和连续版本发布；同一版本不可覆盖，每个项目最多管理 100 台服务器、500 个历史版本。
- 清单只保存 `connectionBindingKey`，不保存 URL、启动命令、Cookie、Token 或账户密码。实际连接配置和凭据由客户设备本地绑定。
- 每项工具同时声明业务名称、技术名称、输入结构哈希、影响类型和审批策略。只有只读工具可以自动放行，写入与外部动作必须人工确认。
- 独立探测器通过真实 MCP 连接读取协议版本、服务器身份和工具输入结构，并用 Ed25519 对完整规范清单哈希及探测结果签名。控制面只接受授权范围内、未过期、能力完全一致的探测。
- 同一个 `serverKey` 的服务器身份哈希一旦建立就不能静默变化；首次可信健康探测作为身份锚随快照持久化、恢复时重验，并受所有历史窗口淘汰保护。确需更换服务器时必须使用新的内部服务器身份并重新审批。
- 可信失败探测命中当前版本时，控制面必须在同一事务中立即停用并写入 `health_disabled` 审计。失败可能表现为无法连接、身份变化、协议漂移或工具结构漂移；这些差异是熔断原因，不能成为丢弃失败探测、继续使用旧健康结果的理由。
- 每次熔断生成新的恢复挑战。只有后续健康探测在 Ed25519 签名载荷中原样带回该挑战，管理员才可重新启用；健康探测本身不会自动开放权限。熔断与恢复引用均随快照持久化并防止被历史窗口淘汰，避免乱序探测、设备时钟偏差或旧健康结果重放解除熔断。
- 每个服务器版本的探测结果还必须签入单调 `probeSequence` 和前一条探测标识。控制面只接受当前链头的直接后继，并在快照恢复时用签名结果重建、校验和保护链头；被历史窗口淘汰的健康或失败结果都不能重新接入当前链。
- 探测历史容量必须为每台服务器预留失败槽。可信失败已经接续当前签名链时，可以优先替换该版本除身份锚外的旧安全引用，并在同一事务成为新的链头和熔断依据；容量压力不能成为继续调用旧连接的理由。
- 新探测和历史验签公钥分离。退役公钥不能签发新探测，但所有副本必须保留它以恢复历史状态。
- 扩展中心的“外部工具”只由可信 MCP 注册表派生。旧扩展目录中的人工 MCP 状态不能让工具进入可使用状态。
- 注册表、当前启用绑定和启用/回滚审计使用共享 PostgreSQL 事务仓储；内存实现只用于测试和单机开发。

## 后果

- 产品经理和初级研发只看到业务动作、可用状态以及是否需要确认，不会看到传输协议、连接地址、工具编码或内部标识。
- stdio 与 Streamable HTTP 只影响设备侧适配器，不能绕过统一的租户、项目、审批和审计策略。
- 本里程碑建立可信注册与可用性判断；一次性调用授权、参数 JSON Schema 校验、Worker 消费和结果证据在后续调用网关中继续闭环。
