# ADR-0003：审批身份与独立证据的信任边界

- 状态：Accepted
- 日期：2026-08-10

## 背景

ForgeX 会同时接收产品审批、Codex Worker 执行结果和独立 Runner 的测试证据。如果控制面直接相信请求体中的“审批人”“已独立验证”或测试数量，开发 Agent 就可能给自己的结果背书，审计记录也无法证明用户批准的是哪一次交付。

## 决策

### Codex 身份与凭据

- Codex 登录态和凭据只保存在客户自己的 Worker 设备上，不上传控制面。
- Worker 主动向控制面发起出站连接，并通过短期会话、代次和 fencing token 领取任务。
- 控制面使用 [Codex SDK](https://developers.openai.com/codex/sdk/) 驱动本地 Worker；实验性的远程 App Server 连接不进入生产关键路径。

### 审批身份与时间

- Web/API 层必须从已认证会话生成 `ApprovalActor`，禁止从业务请求体接受 `actorKey`、`actorName`。
- 审批时间只能来自服务端时钟，客户端不能自报。
- “确认需求”绑定需求版本；“验收结果”额外固化证据、代码仓库、完整提交、产物摘要、Runner 和签名密钥版本。

### 独立验证证据

- Runner 使用 Ed25519 私钥签名，控制面只保存公钥。
- 签名载荷绑定租户、项目、代码仓库、需求版本、完整 Git 摘要、交付产物摘要、每条验收条件、Runner 与 `keyId`。
- Runner 公钥按租户、项目和代码仓库授权；跨范围证据直接拒绝。
- `evidenceKey` 使用 UUID，数据库必须建立租户内唯一约束，防止重放。
- 证据具有最大有效期和有限的未来时钟偏差。
- 工作流快照保存原始签名和完整签名载荷；从数据库恢复时必须通过 `EvidenceAuthority` 重新核对 Runner 授权范围、公钥和 Ed25519 签名，不能把普通 JSON 直接还原为可信 receipt。
- 产品执行最终验收时再次使用服务端时钟检查证据有效期，进程重启不能绕过时效门禁。
- 密钥轮换后保留旧公钥用于历史证据复核，并将其标记为仅验证；退役密钥不能签发新的验证结果。
- 只有独立 Runner 可以持有验证私钥；开发 Worker 不得共享该私钥。

### 发布边界

- 独立验证通过只允许进入产品验收，不等于允许发布。
- 普通页面只打开控制面按需求和版本生成的同源 Preview 地址，不接受 Worker 或 Runner 自报的 URL。
- Preview 制品以 Runner 已签名的 `artifactHash` 内容寻址；仓储按租户、项目、需求、版本和摘要隔离，写入与读取都对实际响应字节重新计算 SHA-256，不允许覆盖。
- 网关不跳转到第三方来源。它返回平台生成的可信外壳，并把制品字节放进没有 `allow-same-origin`、`allow-forms`、`allow-popups` 或 `allow-top-navigation` 的沙箱 iframe；父页面 CSP 只允许 `blob:` 子帧，禁止网络连接、表单和外部导航。
- 生产发布、数据库迁移、权限和网络变更继续使用单独审批与最小权限执行器。

## 后果

- 控制面被读取时不会泄漏 Codex 登录态或 Runner 私钥。
- 一份证据不能被移用到其他租户、项目、仓库、提交或需求版本。
- API 和持久化层必须实现认证上下文、服务端时钟、唯一索引和追加式审计；领域层的直接调用只用于受信任进程内部。
