# ADR-0010：受控 MCP 调用与设备执行闭环

## 状态

已采纳，当前实现仍属于预发布版本。

## 背景

ForgeX 允许可信 MCP 服务向项目提供只读、写入和外部动作。普通成员可以发起调用，但不能把未经确认的写入直接交给设备执行。平台还必须在 MCP 停用、健康证明过期、设备掉线、租约重派和跨仓储短暂失败时保持 fail-closed，并留下可追溯证据。

## 决策

1. MCP 参数定义按租户、项目和 SHA-256 摘要不可变保存。调用记录固化服务版本、Manifest 摘要、输入 Schema 摘要、规范参数摘要和连接绑定。
2. 只读能力可按可信 Manifest 自动排队；写入与外部动作必须由产品负责人或管理员查看人性化、非敏感且精确的业务参数后确认。需要确认的 Schema 必须要求显式填写全部业务字段。控制面拒绝任何 `writeOnly` 或明文凭据参数，凭据只能由 Worker 根据本地连接绑定取得；页面不展示工具编码、连接标识或凭据。
3. 调用只采用签名 Manifest 内的完整工具定义。进入设备队列前、设备最终领取时都重新校验当前 MCP 版本、健康状态、工具定义、连接绑定、Schema 和参数摘要。队列只保存不含凭据的本地连接绑定键。
4. MCP 与需求交付共享不限量设备舰队，但 MCP 使用独立队列配额，不能耗尽正常需求的全部容量；每个租户同时最多保留 100 条未完成 MCP 调用。设备仅通过出站轮询领取任务。
5. 每次执行租约绑定 `workerKey`、设备代次、账户指纹摘要、`assignmentKey` 和单调 `fencingToken`。续租同步到调用记录；只读调用可在租约过期或同一设备重连后由更高 fencing 接管，旧设备结果必须拒绝。写入或外部动作一旦进入执行但未能确认结果，不得自动重做，必须进入“结果待人工核对”。
6. 执行完成采用可恢复的两阶段状态：先在调用事务写入 `completion_pending`，再由 Worker 事务写入永久完成证明，最后把调用固化为成功或失败。完成证明严格绑定 `assignmentKey` 与 `fencingToken`；证明尚未出现且原租约仍有效时，补偿扫描只等待而不误判，租约到期仍无证明时只读调用可重排，写入或外部动作转人工核对。该恢复路径不依赖有时效和容量上限的短期完成墓碑。
7. 取消同样采用持久化 `cancellation_pending`。发起人、产品负责人或管理员可以取消尚未执行的调用；Worker 队列删除成功后才进入 `cancelled`。并发派发后发现已取消时会重新建立待清理状态，清理失败可由后续轮询补偿。
8. 审批、设备租约、完成结果和取消都写入追加式审计。人工取消会记录来源与操作人，系统因能力失效而自动取消时明确记录系统来源。执行审计绑定 Manifest 摘要、参数摘要、设备身份、fencing 与结果摘要，普通成员视图不返回这些内部字段。
9. PostgreSQL 是多副本生产边界。`0008_mcp_invocations.sql` 保存 Schema、调用和审计，`0009_worker_work_kinds.sql` 把工作类型及永久完成证明纳入完成唯一记录；内存实现只用于测试和单机开发。
10. 设备 Worker 使用官方 MCP TypeScript SDK 执行本地连接。`connectionBindingKey` 只作为不含凭据的路由键；设备逐次校验传输类型、工具白名单、实际工具 Schema、规范参数摘要、调用标识、租约与 fencing。`stdio` 启动器及其实际加载的文件参数都必须位于可信本地边界并逐项绑定 SHA-256，普通参数不能承载路径或可执行代码；启动和每次调用都重验文件、父目录 owner/ACL/mode、realpath 与摘要。Streamable HTTP 禁止跨来源重定向并限制响应大小。凭据只存在于设备私有配置和本地连接进程，不回传控制面。
11. Worker 在实际 MCP 调用前持久化执行意图。只读操作遇到进程崩溃可以在同一意图下续租并重试；写入和外部动作一旦越过调用边界但没有形成可信结果，就固定上报“结果待人工核对”，幂等清理队列租约且绝不自动重做。

## 结果

- MCP 目录发生版本变化、停用、熔断或健康证明过期时，不会继续产生新的可执行租约。
- 设备重连、租约超时和重复完成不会造成旧结果覆盖新结果。
- 跨仓储提交无法做到单个数据库事务时，显式中间状态与幂等补偿保证最终可恢复，而不是静默留下队列垃圾。
- 产品负责人看到的是可判断业务影响的内容；Worker 看到的是精确本地路由信息；两者都不会获得不需要的凭据。

## 后续

- 生产发布前增加真实 PostgreSQL 双连接并发与迁移集成测试。
- 生产发布前补充真实 Streamable HTTP 服务与设备断电故障注入测试；当前官方 stdio 协议已纳入自动化集成验证。
- 后续知识库与自动化流水线复用同一审批、租约、fencing、审计和恢复模式。
