# 产品验收发现问题后继续修复

## 用户旅程

作为产品负责人，我希望在需求进入“等待产品验收”后，能够根据 Preview 中发现的问题修订当前需求并生成新版本，以便保留原版本边界，同时让修复重新经过确认、AI 实现和独立验证。

## 成功路径

1. 当前版本已完成独立验证，页面同时提供“确认验收通过”和“反馈问题并继续修复”。
2. 产品负责人选择继续修复后，在当前完整规格上修改业务目标、用户故事、完成标准或待澄清问题。
3. 保存后生成下一版需求，旧版本仍保留在版本历史中。
4. 旧版本的交付候选、Preview 和独立验证证据不再作为新版本的当前验收依据。
5. 新版本进入“内容已更新，等待重新确认”，随后重新确认、安排 AI 实现并独立验证。

## 失败与边界

- 没有修订权限的角色不能看到或调用修订入口。
- 已经进入 AI 实现、已经完成验收或达到 100 版上限时不能继续追加版本。
- 并发修改必须使用当前版本号校验，冲突时提示刷新并合并改动。
- 修订不能直接沿用上一版的 Preview 或可信验证结果，也不能绕过重新确认。
