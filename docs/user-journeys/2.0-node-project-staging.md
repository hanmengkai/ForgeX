# 2.0 P0：实际 TypeScript 项目交付到测试环境

需求方提出团队任务看板：创建任务、查询及筛选、状态流转、输入校验、重复提交保护。真实 Codex 在独立工作树整理需求、设计和实现。产品审核、需求方确认、研发独立设计审核后才允许开发；研发核对代码后，独立测试 Agent 将每条验收条件映射到管理员预先登记的受信套件。测试执行器实际运行 HTTP 检查，测试负责人审核报告，测试运维部署同一提交及制品，需求方验收测试环境。

本轮完成定义是到达“等待发布审批”，测试验收记录已持久化。没有生产执行器，不提交生产联合批准，不连接真实生产。角色操作是有记录的验收输入，不冒充真人签字。

## 行为与失败契约（实现前固定）

- 正式控制面必须使用 PostgreSQL 保存制品原始字节；重启及多个实例读取一致。租户、项目、仓库、摘要和提交共同限定读取范围。重复上传幂等，损坏字节、索引错配及不可变内容冲突拒绝。
- 保留制品交接 v1 的 128 KiB 上限；新增 Node 项目内容协议 v2，包含严格编译的 JavaScript 模块、入口和受信运行时摘要。不执行候选的 npm 脚本或任意 Shell。
- 独立测试计划 v2 使用受信 suiteKey 和 criterionIndex，不带命令、URL 或通过结论。缺少条件、重复映射、未知套件和套件内容变化阻塞。远程网关使用 v3 请求传递计划；原 v2 请求保持兼容。
- TypeScript 编译读取固定源文件及标准库，不读取候选 tsconfig、外部包或工作树外文件；编译失败不可产生成功制品。测试套件及运行时由管理员固定路径、摘要登记，与生成代码分离。
- 候选代码在系统沙箱和 Node 权限约束中运行，不继承凭据及用户环境，不允许出站网络、子进程或读取用户目录；无限循环和非法响应失败。VM 仅限制业务函数，不作为系统安全边界。
- 各 Worker 使用不同私有目录，通过正式制品 API 交接，不共享制品文件系统。上传确认丢失只补传同一自测制品；测试部署确认丢失及 Worker 重启只核对已部署进程和原回执，禁止重复部署。
- 设计未审核时不开发；开发与独立测试身份不同；测试未通过不部署；生产任务在本适配器一律阻塞。
- 验收区分实时 Codex 与显式 fixture。按用户决定，本轮取消托管 CI 接入和新增触发器，保留手动执行的 fixture 与真实 PostgreSQL 回归；实时命令另存模型会话、提交、摘要、测试、审批及恢复证据。
