# 需求执行终端日志

## 用户旅程

作为负责跟进需求交付的产品经理，我希望在“执行记录”中直接看到设备端 Codex/SSH 风格的终端输出，从而能判断任务正在做什么、在哪里失败，而不是只看到重复的概括事件。

作为交付设备管理员，我希望每次需求执行的日志保存在该需求独立的日志目录中，并同步一份到控制面，从而在页面关闭、Worker 重启或交付结束后仍可追溯，且日志不会进入业务代码提交。

作为查看日志的用户，我希望页面默认只显示最后 300 行并持续热更新，同时可以输入任意正整数或选择“全部”，从而在兼顾日常性能的同时不丢失完整排障能力。

## 失败与安全边界

- 浏览器不能直接访问远端 Worker 文件，控制面必须保存受租约约束的日志副本。
- stdout、stderr 和系统事件需要保留来源，但凭据、Bearer Token、密码和私钥不能进入持久化日志或页面。
- 日志上传重复请求必须幂等；旧租约、其他租户、其他需求的日志必须拒绝。
- 展示行数不设产品上限；默认尾部 300 行，“全部”由用户显式选择。
