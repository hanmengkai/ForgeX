# 2.0 交付工作台改版旅程

用户登录后看到自己的待审批、阻塞交付、进行中需求和近期完成。点击事项直接进入对应交付；列表支持按名称搜索以及待我处理、进行中、阻塞、已关闭筛选。需求方可用业务描述提交需求，不接触技术标识。新建需求不永久占用列表上方空间。

详情首屏展示业务目标、当前阶段、下一步和待处理岗位。流程按需求、设计、开发、测试、发布、验收六段展开；独立设计审核作为设计段中的明确步骤，恢复与返工也必须显示真实当前阶段，不用百分比伪装完成进度。当前审核材料优先展示，其余成果、审批记录和 Bug 按类别阅读。

审批区在桌面固定于详情右侧，在窄屏进入首屏阅读顺序。用户知道审核哪个需求、哪版需求或设计、由什么身份确认；通过、异议、驳回提供明确层级。决定提交前检查目标及版本；轮询期间内容变化必须阻止使用旧材料批准新版本。三方放行展示三个岗位的实际确认状态，无权限用户只看等待提示。

导航以工作台、交付需求、我的审批为主线。旧需求工具与外部工具操作确认放入管理区，保留旧链接与业务能力。执行器页优先展示真实连接、能力、当前任务及异常；未获取登录证据时显示“尚未核对”，不以在线状态宣称 Codex 已登录。安装、凭据和命令进入管理员展开区，凭据仍留在设备。

先写以下失败验收：六段流程保留独立设计审核和恢复；搜索筛选不改变审批权限；待办链接打开正确需求；审批取消不写入；轮询版本变化或切换需求后不提交旧意见；异议未处理禁止通过；三方批准缺失继续等待；执行器无心跳或没有登录证据不能显示准备就绪。页面在桌面、390px 窄屏和浅深主题下无横向溢出，键盘能够打开、关闭审批确认并回到原按钮。

使用隔离样板浏览器完成六角色完整闭环及关闭后 Bug 提交。普通回归采用明确的固定样板，不连接真实生产，也不隐式消耗模型额度。
