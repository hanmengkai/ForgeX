# 2.0 全量回归与跨平台失败处理

开发者在 macOS 上直接运行 `npm test`，测试使用短且规范化的本机临时目录；业务工作树、凭据目录和符号链接的权限检查保持严格。测试不需要另设 `TMPDIR`，也不会访问真实生产环境。

设备 Worker 在 macOS 上将单实例 Socket 放在系统规范化短目录，避免默认会话临时目录过长而无法启动。长私有临时路径下仍须真实验证互斥与释放，不只依靠测试环境配置。

验证 Runner 取得当前进程的系统启动标识后，保存和恢复签名证据。第二个 Runner 必须被拒绝；仅在系统确认旧进程不存在或启动身份已变化时回收旧锁。查询失败、权限不足或格式异常时拒绝抢占。macOS 使用启动会话 UUID 与 UTC 进程启动时间；时间粒度为秒，同秒 PID 复用无法区分时保守阻塞，不宣称旧进程已经退出。

扩展管理员按本机系统选择 Windows 或 POSIX 的绝对路径示例。示例必须通过本机公开输入协议；相对路径和其他非法字段仍被拒绝。管理员凭据始终留在本地私有文件中。

产品人员在深色主题查看可信验收结果，并通过当前的主按钮确认验收。测试检查现有组件的颜色和文字对比度，不依赖已删除的 CSS 类名；浅色与深色均须保持可读。

## 修复前失败证据与新增检查

- 原 8 项：macOS 缺少 Runner 启动身份查询导致 6 项日志用例失败；Windows 示例在 macOS 本机路径校验失败；主题用例仍要求不存在的 `.acceptance-action`。
- 未规范化临时目录时，直接运行全量测试出现 45 项失败，包含路径别名和 Unix Socket 长度问题。
- 新增进程查询失败、缺失 PID、权限不足、畸形启动信息和跨重启身份检查；真实 macOS 子进程退出前后查询及多 Runner 抢锁仍需实际验证。
- 新增 POSIX 示例验证与非法相对路径拒绝；主题检查核对当前主按钮与验收结果的实际对比度。
- 浏览器回归发现既有桌面首屏标题区为 132.09375px，超过原 132px 上限；修正实际布局的纵向留白，保持原断言和移动布局。

验证不得降低覆盖率门槛或将原失败用例跳过。数据库和实时模型用例仍按既有显式环境条件运行；本轮保持隔离样板范围。
