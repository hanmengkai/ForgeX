# 2.0 P0：真实 Agent 样板交付

## 用户旅程

需求方提交访客预约目标，真实 Codex 整理需求；产品审核、需求方确认后，另一个 Codex 会话编制设计。研发独立审核设计，批准后才能生成业务代码。可信执行器运行自测，研发审核提交，独立测试执行器逐项验证需求。测试部署和需求方验收后，三种不同角色联合放行隔离发布，三方验收后关闭并保留 Bug 入口。

当前用户模式复用本机 Codex 登录，不复制凭据到控制面，不修改用户配置。明确采用工具权限隔离，而非独立系统用户隔离；只提供经过验证的工作树 MCP，关闭 Shell、浏览器、其他 MCP 和插件。样板业务代码只能实现预约业务函数；HTTP、持久化、健康检查和部署由可信运行时管理。生成代码只在 macOS 系统沙箱及 Node 权限约束下运行，不能访问登录文件、启动子进程或连接外部服务。

## 失败测试（先于实现）

- 登录失败、调用中断或结构化响应错误不能回填模板或默认成功。
- 当前用户模式不继承环境中的 API 密钥，不加载用户 MCP、插件或命令规则。
- 需求和设计阶段修改代码时拒绝结果；设计审核前不能运行开发。
- 未批准的代码、制品摘要不符、运行时版本不符和不支持的沙箱平台均阻塞。
- 恶意业务函数读取本机凭据、发起网络连接、启动子进程或无限循环均不能成功。
- 真实需求中的验收条件必须按固定样板协议逐项映射；不支持的业务不能虚假宣称已覆盖。
- 自动验收脚本以六个测试角色操作审批，保留独立设计审核暂停、拒绝和重新提交证据；此证据不代表真人签字或真实生产验收。

## 本轮边界

样板范围为姓名与时间校验、UUID 编号、幂等与冲突、预约查询，以及关联 Bug 修复的确认说明。真实 AI 决定需求表述、技术设计和业务实现；固定测试探针负责独立验证。所有环境只监听本机回环地址，生产阶段仅指隔离发布环境。
