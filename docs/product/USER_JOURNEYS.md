# 用户旅程

## 产品经理

作为产品经理，我希望用自然语言创建需求并查看 AI 提出的澄清问题，从而在不阅读代码的情况下确认团队理解正确。

作为产品经理，我希望看到“等待确认、正在实现、验证未通过、可以验收”等自然语言状态，从而知道下一步应该做什么。

## 需求分析师

作为需求分析师，我希望每次修改形成新版本，并能比较变化，从而避免开发和验收使用不同基线。

作为需求分析师，我希望验收条件能够关联真实测试证据，从而判断功能是否真的完成。

作为需求分析师，我希望把业务规则按资料和版本发布到项目知识库，并能更新或归档，从而避免 AI 继续引用过期口径。

## 初级研发

作为初级研发，我希望看到任务目标、影响范围、变更摘要和失败原因，从而能够理解并接管 AI 的工作。

作为项目成员，我希望用业务问题检索项目资料，并看到资料名称、版本和段落引用，从而知道答案来自哪里，也知道资料内容只是参考而不是平台命令。

## 平台管理员

作为平台管理员，我希望连接最多五个分别登录 Codex 的设备，并看到设备名称、账户昵称、在线状态和当前工作，而不接触账户凭据。

作为平台管理员，我希望多个需求自动分配给空闲设备，同一账户一次只执行一个需求，从而安全地并行交付。

作为平台管理员，我希望每台设备只在预先绑定的本地仓库中为任务创建独立 worktree，并在租约有效时上报可追溯的本地提交，从而让并行交付不会互相覆盖，也不会把 Codex 凭据交给控制面。

作为产品负责人或初级研发，我希望设备完成只代表“已有待验证提交”，后续仍由独立 Runner 验证确切提交和验收条件，从而避免 AI 用自己的开发测试替自己证明完成。

作为平台管理员，我希望 MCP 外部工具只有在独立探测确认身份、协议和业务能力与已发布清单一致后才能启用，连接凭据仍保留在客户设备本地。

作为产品经理或初级研发，我希望页面只显示 MCP 工具能完成的业务动作和是否需要确认，而不是连接地址、传输协议、工具编码或会话标识。
