# ForgeX 产品章程

## 产品目标

ForgeX 帮助团队把一个已经确认方向的业务需求，转化为可评审的实现、可操作的 Preview 和可复现的验证证据。

首版不承诺从一句话自动生成任意软件，也不自动操作生产环境。

## 首版成功标准

- 一个需求能够经历澄清、批准、实现、验证和 Preview。
- 多个需求能够被分配给最多五台分别登录 Codex 的设备并行处理。
- 账户密码、OAuth Token 和 API Key 不进入控制面。
- 普通用户无需理解内部 ID、分支名和运行编码即可判断进度和下一步。
- 每个结论都能下钻到版本化 Artifact、代码提交和独立 Evidence。

## 首版非目标

- 支持任意技术栈和任意仓库结构。
- 自动合并主分支或自动发布生产。
- 自动执行生产数据库迁移、回滚或事故处置。
- 自研 Kubernetes、通用工作流引擎或通用密钥系统。

## 开源边界

仓库包含控制面、设备 Worker、契约、Web 界面、本地部署和扩展接口。客户凭据、业务代码、私有知识库内容和第三方授权信息不进入仓库。

## 预发布兼容性

当前仓库尚未发布首个可用版本，`schemaVersion: 1` 仍处于定稿阶段，可能发生不兼容调整。首个公开版本发布后，同一 schema 版本只做向后兼容变更；不兼容调整必须提升 schema 版本并提供迁移说明。
