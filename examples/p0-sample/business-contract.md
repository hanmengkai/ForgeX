# 隔离访客预约协议（版本 1）

只实现访客预约，不扩展到其他业务。需求 Agent 应展开目标与用户故事，验收条件固定按以下顺序命名，描述用自然语言详细说明：

1. 有效预约返回编号：POST /appointments，姓名 trim 后长度 2～100，visitAt 是有效日期字符串，requestKey 是 UUID；201 返回 id（使用 input.newId）、name、visitAt、requestKey。
2. 无效预约被拒绝：缺失或无效字段返回 400，body 为中文 error；不改变预约记录。
3. 重复请求保持幂等：相同 requestKey 且姓名、时间一致返回 200 和原记录；不同内容复用标识返回 409。重复不追加记录。
4. 预约可以查询：GET /appointments/:id 返回 200 和原记录；找不到返回 404。其他未知接口返回 404。

修复需求（标题以“修复：”开头且涉及确认说明）增加第五条“预约返回确认说明”：成功创建（201）、幂等重试（200）和成功查询（200）的响应均含 display="预约已确认"，保留前四项。display 仅为响应附加字段，不存入记录数组或持久化文件；返回响应副本，不修改已有记录。已有不含 display 的记录查询或重试时同样返回该说明，无需迁移或回填。错误响应不添加 display。首次需求不需要 display。这些修复细则已由本轮样板需求方确认，不存在待定选择。

开发 Agent 只能编写 appointment.js，内容为普通 JavaScript，定义顶层 function handleAppointment(input)。禁止 import/export、命令或网络调用。可信运行时通过隔离 VM 调用函数，不提供 process、require、fetch 或宿主对象。输入为 {method,url,body,appointments,newId}，body 是请求 JSON，appointments 为当前记录数组。函数同步返回 {status,body,appointments}。status 仅允许 200/201/400/404/409。新增预约返回新的记录数组；其他响应返回原数组。不要依赖函数调用间的全局状态。

HTTP、健康检查、页面、写入序列、文件持久化由可信运行时实现，不要另写服务器。每次调用在独立 VM 中运行，上限 100ms；代码最多 64KiB，最多 2000 条样板记录。不安装任何依赖。开发阶段只声明代码完成，真实自测由可信执行器负责。

设计 Agent 应设计本协议的业务函数与可信运行时的配合，说明接口、数据兼容性、测试及恢复，保留独立研发审核环节。不能设计需要额外权限的实现。

独立测试 Agent 只能返回测试计划；probes 按需求的 criterionIndex 映射：0=create，1=invalid，2=idempotency，3=query，修复时 4=display。实际 HTTP 探针分别核验创建 UUID、无效输入、幂等冲突、查询一致性和确认说明。不要在计划中捏造执行结果。

## 本轮已确认的细则（需求方案不应再次列为待澄清）

- name 必须是字符串，trim 后用于长度校验、保存、返回和幂等比较；长度按 JavaScript UTF-16 length，范围 2～100。
- visitAt 必须是字符串且 Number.isFinite(Date.parse(visitAt))，允许过去时间，不限制具体格式或时区；按原字符串保存、返回和比较，不做时间点归一化，也不额外检查日历溢出。
- requestKey 必须是小写十六进制 8-4-4-4-12 格式 UUID 字符串，允许各种版本，按原字符串比较，不接收大写或首尾空白。可信运行时保证 input.newId 是有效、唯一 UUID，现存预约记录是有效 JSON 且 requestKey 唯一。
- 校验无效输入优先于幂等冲突。所有错误响应 body 使用 {error:中文说明}，具体文案由实现决定。
- URL 按输入字符串精确匹配；查询参数、尾斜杠、路径编码及不支持的方法均返回 404，不需规范化。查询不存在编号返回 404。
- 达到 2000 条记录时，新的创建请求返回 400 和中文容量提示，重复请求仍按幂等协议处理。本轮测试无需生产级容量、性能、权限或时区功能；这些属于后续接入范围。
- 可信运行时串行处理写请求，成功创建后先原子写入临时文件并 rename，再返回 201。持久化失败返回 400，不替换内存记录；重启从原文件恢复。每个环境目录与其他环境隔离。业务函数返回同步数据，不能自行写文件或启动服务器。
- 产品、需求方已确认上述协议足够用于本轮隔离闭环，不需要额外业务决策。真实的未知问题可以保留，已确认细则不列为开放问题；建议及非本轮功能写入方案说明而不是阻止本轮交付。
